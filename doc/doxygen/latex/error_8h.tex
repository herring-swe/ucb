UCB handles errors in the following way\+:
\begin{DoxyItemize}
\item Fatal errors, user errors and warnings\+:
\begin{DoxyItemize}
\item Are {\bfseries{reported}} to a single error handling function.
\item By default these errors are written to stderr, but the program is {\bfseries{not}} terminated.
\item The user can override the default error handler, with \doxylink{error_8h_a244d144e04b99a8ec2db4da0cad769e9}{ucb\+\_\+error\+\_\+set\+\_\+func}.
\item Examples or each type\+:
\begin{DoxyItemize}
\item Fatal error\+: Out of memory. Functions try to return early, but no guarantee.
\item User error\+: Invalid arguments or states in input. Functions return early.
\item Warning\+: Recoverable errors where fallbacks may be used to continue.
\end{DoxyItemize}
\end{DoxyItemize}
\item Complex errors\+:
\begin{DoxyItemize}
\item For more complex errors, where input may lead to invalid results, arithmetic failures or similar, the function will {\bfseries{throw}} an \doxylink{structucb__error}{ucb\+\_\+error}.
\item These functions takes a \doxylink{structucb__error}{ucb\+\_\+error} double pointer as argument and must return a type such as bool or NULL pointer which can indicate that an error has occured.
\item The \doxylink{structucb__error}{ucb\+\_\+error} contain an \doxylink{types_8h_a7b51af80e3e90400b56704878d961344}{ucb\+\_\+ecode} and a message of the error.
\item Errors may be ignored by not providing an \doxylink{structucb__error}{ucb\+\_\+error} pointer, but this is not recommended.
\item Any errors thrown must be handled by the caller or propagated. The error is cleared by calling \doxylink{error_8h_afb85daa79ddb67d6361e584618eafaaa}{ucb\+\_\+error\+\_\+clear}.
\end{DoxyItemize}
\item Otherwise for simple functions, like getters, any input NULL pointers may be ignored if the return type allows it.
\item All functions must document if they behave differently than above rules. 
\end{DoxyItemize}
